# dms-fdmcorrect

`dms-fdmcorrect` corrects the counts of single-nucleotide variants (SNVs) in deep mutational scanning (DMS) data for sequencing and PCR errors, using the programmed variant library itself as the error control. It thereby avoids the need for additional wildtype template processing and deep sequencing.

```
  >>>>>>XXX>>>>>>>>>>>>>>>>>
  >>>>>>XXX>>>>>>>>>>>x>>>>>          \(o_o)/           A2P    |||||||||  ->
  >>>>>>>>>>>>>>>>>>>>x>>>>>   ==> dms-fdmcorrect ==>   L109M  |||||||||  ->  ||||||
  >>>>>>>>>>>>>>>XXX>>>>>>>>                            E46A   |||||||||  ->  ||||||||
  >>>>>>>>>>>>>>>>>>>>>>>>>>

  XXX programmed codon (anchor)    x single-nucleotide change    XXX + x: false double
```

In a saturation mutagenesis library of programmed single-codon variants, a read should carry only one changed codon. A read that carries a programmed multi-nucleotide codon variant (the *anchor*) together with a single-nucleotide change some codons away is a **false double mutant**: almost always a sequencing or PCR error on top of the anchor. Per SNV *j*, the false-double reads *F<sub>j</sub>* set against the anchor reads that could have shown the error, the exposure *M<sub>j</sub>*, give the error rate *e<sub>j</sub>*. The expected error reads *e<sub>j</sub>* × coverage are then subtracted from the SNV's count. In our tests (see Wehnert et al., bioRxiv (in prep)), resulting count error profiles correlate with those from sequencing of an unmutated template at r = 0.85-0.95.

- **Estimator:** empirical-Bayes Gamma-Poisson. Each SNV's rate is shrunk towards the mean of its trinucleotide context, which is shrunk towards its substitution type, in proportion to how little evidence the SNV has. A per-SNV maximum-likelihood estimate (*F/M*) is also available.
- **Pooling:** libraries prepared and sequenced together share their evidence and one set of rates; each is corrected at its own coverage.
- **Genuine double mutants:** in specific mutagenesis workflows, such as nicking, two independent mutations can integrate into one molecule and therefore into subsequent DMS selection workflows. This 'genuine double mutant' rate can be measured on reads with two programmed multi-nucleotide variants, which are very unlikely to be generated by PCR or sequencing error, and removed from the evidence.

It is an R package (dependency: data.table) with a command-line interface, and the key error-correction step of the [nf-core/deepmutscan pipeline](https://nf-co.re/deepmutscan). Its input is a variant count table from raw sequencing alignment, such as the one generated by [dms_count](https://github.com/MaximilianStammnitz/dms-count). A full-depth library takes a few CPU seconds.

## Installation

From Bioconda (command-line tool and R package):

```bash
conda install -c conda-forge -c bioconda dms-fdmcorrect
```

In R, from GitHub:

```r
install.packages("remotes")
remotes::install_github("MaximilianStammnitz/dms-fdmcorrect")
```

The command-line script is then at `system.file("scripts", "dms-fdmcorrect", package = "fdmcorrect")`.

## Quick start

The package bundles two GID1A libraries (input and output, thinned to 5 % of their reads):

```bash
X=$(Rscript -e 'cat(system.file("extdata", package = "fdmcorrect"))')
dms-fdmcorrect run \
    --counts $X/GID1A_input.variant_counts.tsv.gz $X/GID1A_output.variant_counts.tsv.gz \
    --codon_library $X/GID1A_codon_library.csv.gz --reference $X/GID1A.fasta \
    --pool GID1A --outdir gid1a
```

The same in R:

```r
library(fdmcorrect)
x <- function(f) system.file("extdata", f, package = "fdmcorrect")
fdm_run(c(x("GID1A_input.variant_counts.tsv.gz"), x("GID1A_output.variant_counts.tsv.gz")),
        codon_library = x("GID1A_codon_library.csv.gz"), reference = x("GID1A.fasta"),
        outdir = "gid1a", pool = "GID1A")
```

The corrected counts are in `gid1a/GID1A_input/fdm_corrected_counts.csv` and `gid1a/GID1A_output/fdm_corrected_counts.csv`.

## Input

1. **Variant counts per library**, as written by [dms_count](https://github.com/MaximilianStammnitz/dms-count): tab-separated, no header, one row per distinct combination of changes in a read, with the columns counts, cov, mean_length_variant_reads, varying_bases, base_mut, varying_codons, codon_mut, aa_mut, pos_mut. The table must keep the reads with two changed codons, which carry the evidence. May be gzip-compressed.
2. **Codon library**: a CSV with columns `Codon_Number` (1 = first codon of the reading frame), `wt_codon` and `Variant`, one row per programmed codon at each position. nf-core/deepmutscan writes it as `possible_mutations.csv`. For an NNK library:

   ```r
   ref <- toupper(paste(readLines("reference.fasta")[-1], collapse = ""))
   orf <- substring(ref, 352, 1383)                       # the reading frame
   wt  <- substring(orf, seq(1, nchar(orf), 3), seq(3, nchar(orf), 3))
   nnk <- as.vector(outer(outer(c("A", "C", "G", "T"), c("A", "C", "G", "T"), paste0), c("G", "T"), paste0))
   lib <- do.call(rbind, lapply(seq_along(wt), function(i)
       data.frame(Codon_Number = i, wt_codon = wt[i], Variant = setdiff(nnk, wt[i]))))
   write.csv(lib, "codon_library.csv", row.names = FALSE)
   ```

3. **Reference**: the FASTA the reads were aligned to (one sequence). SNV positions and wild-type bases are checked against it.

Pooling assumes one error process: libraries prepared, amplified and sequenced together. `run` pools all the libraries it is given. For anything else, run the steps separately with one `estimate` per pool.

## Steps

| step | command | per | output files |
| --- | --- | --- | --- |
| programmed variants | `library` | library | `fdm_library_variants.csv`: the observed single-codon variants of the codon library, with `counts_per_cov` |
| evidence | `evidence` | library | `fdm_evidence.csv` (per SNV: `F`, `M`, substitution `type`, trinucleotide `context`), `fdm_evidence_summary.csv`, `fdm_distance_profile.csv`, `fdm_exposure_by_distance.csv` |
| estimate | `estimate` | pool | `fdm_rates.csv` (per SNV: pooled `F`, `M`, genuine-double reads `G`, `prior_mean`, `prior_nu`, `shrinkage_weight`, rate `e`), `fdm_prior_fit.csv` (each prior class), `fdm_rates_per_library.csv` (each library alone, for comparison), `fdm_kappa_profile.csv` (genuine-double rate by codon distance) |
| correct | `correct` | library | `fdm_corrected_counts.csv`: `counts` and `counts_per_cov` corrected, originals in `counts_raw` and `counts_per_cov_raw`; `fdm_seq_error_rate.csv`: every possible SNV of the reference with its evidence and rate |

`dms-fdmcorrect <command>` without options lists what each command needs; `dms-fdmcorrect --help` lists them all.

| option | default | meaning |
| --- | --- | --- |
| `--max_fd_dist` | 40 | farthest anchor, in codons from the SNV |
| `--min_fd_dist` | 13 | anchors this close or closer are not used: within the footprint of one mutagenic oligonucleotide (a nicking primer, or an oligo of a synthesised pool such as Twist or IDT), the false doubles are dominated by that oligo's own recurrent synthesis errors, which travel with the anchor |
| `--method` | `eb` | `eb` empirical Bayes, or `mle` (*F/M*, zero for every SNV without a false double) |
| `--prior` | `trinucleotide_context` | or `substitution_type` (6 classes only) |
| `--no_genuine_doubles` | | keep genuine double mutants in the evidence |
| `--wildtype` | | `estimate` for a library of the unmutated template, which has no anchors: evidence summed, no rates |

Notes:

- Only SNVs are corrected. Two- or three-nucleotide codon changes are assumed to be counted with negligible error.
- A pool with fewer than 100 false-double reads is left uncorrected.
- An SNV without any anchor in its window gets the prior mean of its class with `eb`, and stays uncorrected with `mle`.

## Tests

`tests/testthat` runs the bundled example and compares every output table with the outputs of nf-core/deepmutscan's error-correction modules on the same input (`R CMD check`, or `testthat::test_local()`). On Linux they are byte-identical; the test allows for last-digit differences of other maths libraries.
